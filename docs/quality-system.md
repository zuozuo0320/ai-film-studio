# AI 影视作品质量保障体系设计

> 目标：让系统**稳定、可复现地输出高质量 AI 影视作品**。本文档与 [architecture.md](./architecture.md) 配套：架构文档解决"怎么跑通和规模化"，本文档解决"怎么保证产出质量"。
>
> 六大支柱按优先级排序：人物一致性 → 提示词工程流水线 → 多版本生成与自动评分 → 质量关卡状态机 → 镜头衔接与成片质量 → 数据飞轮。

---

## 1. 人物一致性体系（最高优先级）

人物形象跨分镜漂移（长相、服装、体型变化）是 AI 影视目前最大的质量短板，是产品质量的生死线。

### 1.1 角色资产包（Character Asset Pack）

模特主体不再只存一张参考图，升级为结构化的"角色资产包"：

```
CharacterAssetPack
  ├─ ref_images[]        # 多角度参考图：正面 / 侧面 / 全身
  ├─ appearance_spec     # 标准化外貌描述（结构化字段：脸型/发型/肤色/体型/年龄感…）
  ├─ outfits[]           # 服装/造型版本（每个版本：名称 + 描述 + 参考图）
  └─ identity_ref        # 万相人物一致性/IP 保持所需的形象引用（注册后获得）
```

- 用户创建模特主体时引导上传多角度参考图，缺角度时给出提示。
- 外貌描述模板化录入，LLM 辅助从参考图自动生成初稿，用户确认。
- 服装/造型按"版本"管理：同一角色在不同场景可绑定不同造型版本，分镜分析时由 LLM 按剧情自动选版本。

### 1.2 出图时强制注入角色资产

- 分镜出图请求由系统自动组装：`分镜提示词 + 角色外貌描述 + 对应造型版本描述 + 参考图`，不允许裸提示词出图。
- 使用**万相的人物一致性 / IP 保持能力**：将角色参考图注册为形象引用，出图时传入，保证跨分镜形象统一。

### 1.3 自动一致性校验

```
出图完成 ──► 人脸/特征相似度模型（如 ArcFace/InsightFace 人脸 embedding 余弦相似度）
            对比新图中人物与角色参考图
   ├─ 相似度 ≥ 阈值 ──► 通过，进入下一关卡
   └─ 相似度 < 阈值 ──► 自动重新生成（最多 N 次），仍不达标则标记"需人工处理"
```

- 阈值与重试次数可按项目配置；多人物分镜逐人校验。
- 校验结果（相似度分数）随图片一起展示，给用户量化参考。

## 2. 提示词工程流水线（质量的源头）

### 2.1 多轮分析，而非一步到位

LLM 分析剧本拆为三个阶段，逐层细化：

```
阶段一：剧本理解        → 全局摘要、题材/情绪基调、场景与人物关系图
阶段二：视觉风格定调     → 产出项目级"风格 Bible"：
                          统一色调、镜头语言偏好、画幅比例、美术风格、光影基调
阶段三：逐镜提示词生成   → 在风格 Bible 约束下，为每个分镜生成
                          summary / image_prompt / keywords[] / video_prompt
```

每个阶段的产出均落库且用户可编辑；修改风格 Bible 后可一键重新生成全部分镜提示词。

### 2.2 提示词模板库（结构化拼装）

提示词不靠 LLM 自由发挥，而是按维度结构化拼装：

| 维度 | 示例取值 |
| --- | --- |
| 景别 | 特写 / 近景 / 中景 / 全景 / 远景 |
| 运镜 | 推 / 拉 / 摇 / 移 / 跟 / 固定机位 |
| 光影 | 顺光 / 逆光 / 侧光 / 低调光 / 黄金时刻 |
| 情绪 | 紧张 / 温馨 / 压抑 / 欢快 / 悬疑 |

- 系统维护各维度的提示词片段模板（含万相/可灵各自的最佳实践写法），LLM 阶段三只负责"选维度取值 + 填充剧情内容"，由模板引擎拼装成最终提示词。
- 模板库可持续运营更新（与第 6 节数据飞轮联动）。

### 2.3 风格 Bible 全局注入

- 每个项目持有一份风格 Bible（阶段二产出），出图/出视频时自动作为前缀/约束注入每一镜的提示词，保证全片风格统一。
- 风格 Bible 支持从预设风格包（电影感写实 / 国风 / 赛博朋克…）一键初始化。

## 3. 多版本生成 + 自动评分筛选

### 3.1 图片：每镜多候选 + 自动排序

```
每镜出图 N 张候选（默认 3-4，可配）
  ──► 自动评分：
      ① 美学评分（aesthetic predictor）
      ② 提示词对齐度（CLIP score：图片 ↔ image_prompt）
      ③ 人物一致性分（第 1.3 节）
  ──► 加权综合分排序 ──► 前端按分数排列供用户挑选，最差的可自动淘汰
```

### 3.2 视频：关键镜头多版本

- 分镜带"重要度"标记（LLM 分析时产出，用户可改）；关键镜头自动生成多版本视频，普通镜头单版本控制成本。
- 视频版本同样自动评分淘汰明显劣化版本（见 4.2 检测项），用户只在优质版本中挑选。

## 4. 质量关卡（Quality Gate）状态机

在原有 Shot 状态机中插入两个质量关卡：

```
pending → queued → image_running → image_review(关卡一)
            ▲              │ 自动校验失败/用户打回 ──► 重新出图
            │              ▼ 自动校验通过 + 用户确认
            │         video_running → video_qc(关卡二) → done
            │              │ 自动检测不合格 ──► 自动重试（≤N 次）
            └──────────────┘ 重试耗尽 ──► failed(需人工处理)
```

### 4.1 关卡一：分镜图审核

- **必须通过才能进入视频生成**：自动校验（一致性 + 评分阈值）+ 用户确认双重关卡。
- 目的：避免在差图上浪费视频生成成本（视频贵且慢，图片是最便宜的质量卡点）。

### 4.2 关卡二：视频自动质检

视频生成后自动检测常见劣化，不合格自动重试：

| 检测项 | 方法 |
| --- | --- |
| 肢体畸变 | 抽帧 + 人体姿态估计，检测异常关节/多余肢体 |
| 画面抖动 | 帧间光流/特征点位移方差超阈值 |
| 首尾帧跳变 | 首尾帧与源图的结构相似度（SSIM）突变检测 |

## 5. 镜头衔接与成片质量

### 5.1 相邻分镜共享上下文

- 利用**可灵的首尾帧控制能力**：上一镜的尾帧可作为下一镜的首帧参考，保证转场连贯。
- 分镜分析时 LLM 标注"衔接关系"（硬切 / 连贯转场 / 场景切换），仅对连贯转场启用首尾帧链接。

### 5.2 全片节奏控制

- 摒弃"每镜统一 5 秒"：LLM 分析阶段为每镜标注**时长与节奏**（快切 1-3s / 常规 5s / 长镜头 8-10s），作为可灵生成参数。
- 项目级节奏曲线可视化（时间轴上看每镜时长分布），用户可整体调节。

## 6. 数据飞轮

把用户行为沉淀为质量优化数据，持续改进自动生成质量：

```
采集：用户选了哪张候选图 / 改了什么提示词（diff）/ 重生成了几次 / 打回原因
  ──► 归因分析：哪些模板片段/风格组合胜出率高、哪些提示词写法导致重生成
  ──► 反哺：
      ① 更新提示词模板库的默认片段与权重（第 2.2 节）
      ② 调整自动评分的加权参数（第 3.1 节，向用户实际偏好对齐）
      ③ 长期：积累 (提示词, 选中图) 偏好数据，可用于微调排序模型
```

落库为 `GenerationFeedback` 事件表（user_id / shot_id / 事件类型 / before / after / 时间戳），离线分析按周产出模板库优化建议。

## 7. 落地优先级

| 阶段 | 内容 | 说明 |
| --- | --- | --- |
| P0 | 第 1 节（角色资产包 + 万相一致性 + 自动校验）、第 2 节（多轮分析 + 模板库 + 风格 Bible） | 见效最快，决定质量下限 |
| P1 | 第 3 节（多版本 + 评分）、第 4 节（双质量关卡） | 提升质量上限，控制视频成本 |
| P2 | 第 5 节（首尾帧衔接 + 节奏）、第 6 节（数据飞轮） | 成片级体验与长期质量迭代 |
